# Status

What BMWflow does today, its known limits, and the planned extensions.

## Implemented

| Feature | Where |
|---|---|
| KPZ model, NLO (`f(p, w)`) and LO (`f(p)`) approximations, `f_lambda = 1` in all dimensions | `flow/models/model_kpz.py` |
| Dimensionless flow in RG time, explicit Euler step | `flow/evolution.py` |
| Two-grids scheme: initial condition of the large-p equation recorded at each exit, optional `I_dimful` | `flow/evolution_two/` |
| Generic LO model for modules generated by FRGscalarMSR (contract version 3: functions without eta, such as KPZ's f_λ) | `flow/models/model_generated.py`, [guide](guide/generated-models.md) |
| Regulators: Wetterich-type, exponential, and variants | `flow/regulator.py` |

## Known limitations

- **Generated models**: LO only, one fixed dimension per module, no evo2 (`Evo2KPZ` is NLO-only).
- **Time stepping**: explicit Euler with a fixed step `ds` only.
- **Unused code**: the Numba and JAX versions of the KPZ kernels (`kpz_numbafunc.py`, `kpz_jaxfunc.py`, `model_kpz_jit.py`,
  `maths_utils_numba.py`, `maths_utils_jax.py`) are not imported; `flow/models/__init__.py` imports the NumPy `ModelKPZ`.
  They are not in the API reference.
- **Interactive prompt**: `Evolution` asks on stdin when the output directory exists; a non-interactive run must write to a
  new directory.

## Not implemented and future directions

- Navier–Stokes model.
- Crank–Nicolson algorithm to integrate the dimensionful flow.
